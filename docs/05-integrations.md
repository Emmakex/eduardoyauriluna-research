# Academic Integrations

This document is the source of truth for external academic/research platform connections.

## Integration policy

Each integration must record:

- Purpose
- Official identifier/profile URL
- Authentication method
- Data direction
- Data ownership/source of truth
- Sync limitations
- Security requirements
- Implementation status

Never commit credentials, OAuth secrets, access tokens or private keys.

---

## ORCID

**Priority:** Critical  
**Status:** Planned  
**Role:** Canonical external researcher identifier

### Intended use

- Authenticate researcher identity using OAuth
- Read public ORCID record data
- Link publications and works to the website
- Display canonical ORCID identifier
- Prepare for deeper write integration only if an appropriate ORCID Member API path is available in the future

### Preferred data direction

Initially: **ORCID → WordPress**

### WordPress fields

- ORCID iD
- Public profile URL
- Biography
- Keywords
- Education
- Employment
- Works
- External identifiers
- Last sync timestamp

## Google Scholar

**Priority:** Critical  
**Status:** Planned  
**Role:** Discovery, citation visibility and public author profile

### Important design constraint

Do not base the product on scraping Google Scholar.

### Intended use

- Store Google Scholar profile URL / profile ID
- Generate Scholar-friendly publication pages
- Generate bibliographic meta tags such as `citation_title`, `citation_author`, `citation_publication_date`, `citation_pdf_url`
- Support manual BibTeX / CSV import if needed
- Track public profile linkage without claiming an official sync when one does not exist

### Preferred data direction

Profile link + Academic SEO rather than API synchronization.

---

## Zenodo

**Priority:** Critical  
**Status:** Planned  
**Role:** DOI-backed publication of research outputs

### Intended use

- Publish/record preprints, technical reports, datasets and research software
- Store Zenodo record IDs and DOI values
- Link GitHub releases to archived research software where appropriate
- Retrieve published metadata

### Preferred data direction

**WordPress ↔ Zenodo**, subject to explicit user authorization and safe publishing workflows.

---

## OpenAlex

**Priority:** High  
**Status:** Planned

### Intended use

- Resolve author identity
- Discover works and citations
- Retrieve concepts/topics and co-author relationships
- Enrich research impact dashboards

### Preferred data direction

**OpenAlex → WordPress**

---

## Crossref

**Priority:** High  
**Status:** Planned

### Intended use

Given a DOI, retrieve authoritative bibliographic metadata to reduce manual entry:

- Title
- Authors
- Publication date
- Journal/conference
- Publisher
- DOI URL
- Container title
- Volume / issue where available

### Preferred data direction

**Crossref → WordPress**

---

## Web of Science

**Priority:** Medium  
**Status:** Future

Store ResearcherID/profile data when available. Any API features depend on entitlement/access and must not be assumed.

## Scopus

**Priority:** Medium  
**Status:** Future

Store Scopus Author ID once an author profile is actually generated by indexed output. Do not fabricate or prematurely assign an identifier.

## ResearchGate

**Priority:** Low / visibility  
**Status:** Future

Use primarily as a linked public profile rather than a system of record.

## Connection status model

Suggested Manager states:

- `not_configured`
- `configured`
- `connected`
- `syncing`
- `error`
- `read_only`
- `manual_link`

Each connection should expose:

- Status
- Identifier
- Last successful sync
- Last error
- Data direction
- Permissions granted
- Disconnect action
