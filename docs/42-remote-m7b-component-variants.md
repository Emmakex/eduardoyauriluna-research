# M7b — bounded section/component variants from ChatGPT

Status: implementation / CI acceptance

M7b adds controlled visual variants for existing Theme-owned markup without allowing remote HTML, class names, CSS rules, section hiding or content reordering.

## Operating model

`Eduardo → ChatGPT → authenticated Manager /design/variants → exact enum state → Theme-owned body classes → fixed Theme CSS`

The Theme remains the frontend authority. The semantic DOM remains unchanged.

## Why variants are separate from M7a tokens

M7a stores palette, typography and density in `eduardo_research_design`.

M7b stores component presentation in a separate Theme option:

`eduardo_research_design_variants`

This keeps the M7a lifecycle/backward compatibility intact and lets component variants evolve without changing the established token state shape.

Default M7b state:

```json
{
  "hero": "orbit",
  "sections": "layered",
  "cards": "bordered",
  "collections": "editorial-grid"
}
```

## Bounded dimensions

### Hero
- `orbit` — current two-column research-system orbit presentation
- `editorial` — single-column editorial copy with the same aria-hidden orbit visual below
- `compact` — text-first hero; only the decorative aria-hidden visual is suppressed

### Sections
- `layered` — current tonal treatment
- `plain` — transparent/white-space-led sections with boundary lines
- `bands` — alternating Theme-owned tonal bands

### Cards
- `bordered` — current bounded card surface
- `lifted` — stronger fixed Theme shadow/hover depth
- `quiet` — transparent low-chrome surface with retained boundaries

### Collections
- `editorial-grid` — current editorial grid
- `compact-grid` — denser fixed grid for scanning larger sets
- `list` — single-column list presentation using the same article/card markup

## Theme implementation

`inc/research-design-variants.php` owns:
- variant contract/version/defaults;
- state sanitation;
- current variant state;
- deterministic `body_class` additions;
- fixed variant CSS;
- public variant contract.

Only classes generated by the Theme are added:

`research-variant-{dimension}-{known-preset}`

Examples:
- `research-variant-hero-editorial`
- `research-variant-sections-bands`
- `research-variant-cards-lifted`
- `research-variant-collections-list`

Remote callers never supply a class name.

## Semantic/accessibility boundary

M7b changes presentation only.

It does not:
- modify heading levels;
- change landmark elements;
- change link destinations;
- reorder content;
- remove evidence/content sections;
- inject HTML;
- inject arbitrary classes;
- inject arbitrary CSS;
- load remote resources;
- change M7a palette/typography/density state.

The fixed CSS includes a `prefers-reduced-motion: reduce` rule disabling lift transitions and removes hover transforms on narrow/mobile layouts.

The `compact` hero may hide only the orbit visual, which is already `aria-hidden="true"`; researcher identity and hero text/actions remain present.

## Remote API

Scopes remain:
- `design.read`
- `design.write`
- `operations.apply`
- `operations.rollback`

Routes:
- `GET /research-manager/v1/design/variants`
- `POST /research-manager/v1/design/variants/plan`
- `GET /research-manager/v1/design/variants/plans/{plan_id}`
- `POST /research-manager/v1/design/variants/plans/{plan_id}/apply`
- `GET /research-manager/v1/design/variants/operations/{operation_id}`
- `POST /research-manager/v1/design/variants/operations/{operation_id}/verify`
- `POST /research-manager/v1/design/variants/operations/{operation_id}/rollback`

## Lifecycle

`Inspect → Plan → explicit Apply → Verify → Rollback`

Preview returns:
- exact before/after variant state;
- changed dimensions;
- exact Theme-generated body classes;
- semantic/content-order safety flags.

Apply requires:
- same remote connection;
- explicit confirmation;
- non-expired plan;
- exact unchanged variant revision.

Verify checks:
- exact state;
- exact post-Apply revision;
- all body classes match the Theme's bounded naming contract;
- CSS contains no `url(`, `@import` or script surface;
- semantic/content-order flags remain true.

Rollback refuses to overwrite a variant state changed after Apply.

## M7b repository/CI definition of done

Fresh WordPress must prove:
1. four variant dimensions and at least three bounded choices per dimension;
2. safety contract explicitly forbids arbitrary HTML/classes/CSS/section hiding;
3. `design.read` scope enforcement;
4. capability discovery exposes `/design/variants`;
5. unknown dimension and class-like arbitrary values are rejected;
6. Preview does not mutate M7a or M7b state;
7. Apply requires confirmation;
8. all four variants apply exactly;
9. M7a token state remains unchanged;
10. generated body classes are all Theme-bounded;
11. fixed CSS contains all selected variant selectors and reduced-motion protection;
12. Verify succeeds;
13. stale Preview is rejected;
14. Rollback restores exact M7b baseline and leaves M7a unchanged;
15. historical Theme and Manager CI remains green.
